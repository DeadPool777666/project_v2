## 🔧 Технические детали

### Структура данных новостей в Firestore

```typescript
{
  id: string,              // Firestore document ID
  title: string,           // Заголовок
  description: string,     // Краткое описание
  content: string,         // Полный текст
  imageUrl: string,        // URL изображения
  publishedAt: string,     // Дата публикации
  category: string,        // Категория (technology, business, sports, etc.)
  source: string,          // Источник новости
  author?: string,         // Автор
  createdAt: string,       // Дата создания в базе
  updatedAt: string,       // Дата п��следнего обновления
  externalId?: string      // ID из внешнего API (для избежания дубликатов)
}
```

### Backend архитектура

```
Frontend (React) 
    ↓
Firebase Firestore ← Хранение новостей, комментариев, избранного
    ↑
    ↓ синхронизация
Supabase Edge Functions (Backend)
    ↓
Supabase KV Store ← Временное хранение из API
    ↑
NewsData.io API ← Источник новостей
```

### Endpoints

1. **GET `/make-server-e2f30d05/fetch-news`**
   - Получает новости из NewsData.io API
   - Сохраняет в Supabase KV Store
   - Возвращает статистику (сколько новостей загружено)

2. **GET `/make-server-e2f30d05/news`**
   - Получает все новости из KV Store
   - Используется для синхронизации с Firebase

3. **DELETE `/make-server-e2f30d05/news/:externalId`**
   - Удаляет новость из KV Store (для админов)

## 🔄 Как работает автоматическое обновление

1. **Запуск приложения** → Через 10 секунд первый запрос к API
2. **Каждый час** → Автоматический запрос к API
3. **Backend** → Получает новости из NewsData.io
4. **Проверка дубликатов** → По externalId
5. **Сохранение** → В Supabase KV Store
6. **Синхронизация** → Автоматическая синхронизация с Firebase Firestore
7. **Отображение** → Новости появляются в приложении

## 📊 Лимиты и производительность

- **NewsData.io Free:** 200 запросов/день
- **Использование:** ~24 запроса/день (1 раз в час)
- **Запас:** ~176 запросов для ручного обновления
- **Firebase Firestore Free:** 50K чтений, 20K записей/день
- **Производительность:** Оптимально для тысяч пользователей
